# Контракт API — Expense Tracker

Доповнює [`spec.md`](../spec.md): spec описує намір і правила, цей файл — точні маршрути, формати й коди. Схема БД — [`server/db/schema.sql`](../server/db/schema.sql).

## Маршрути

| Метод і шлях | Призначення | Успіх | Помилки |
|---|---|---|---|
| `GET /expenses` | Усі витрати, нові спочатку (`spent_at` DESC, `id` DESC) | `200` | — |
| `POST /expenses` | Створити витрату | `201` (+ `warning`) | `400` |
| `PUT /expenses/:id` | Замінити всі поля витрати | `200` (+ `warning`) | `400`, `404` |
| `DELETE /expenses/:id` | Видалити витрату | `200` | `404` |
| `GET /categories` | Усі категорії | `200` | — |
| `POST /categories` | Створити категорію | `201` | `400` |
| `PUT /categories/:id` | Замінити назву й ліміт | `200` (+ `warning`) | `400` (зокрема для «Інше»), `404` |
| `DELETE /categories/:id` | Перенести витрати в «Інше» і видалити категорію | `200` | `400` (для «Інше»), `404` |
| `GET /reports/last-30-days` | Звіт за `[today - 29, today]` зі станом лімітів | `200` | — |
| `GET /reports/monthly?month=YYYY-MM` | Звіт за календарний місяць | `200` | `400` |
| `GET /version` | Короткий Git SHA | `200` | — |

## Загальні правила

- **`400`** — невалідне тіло або query-параметр; дані не змінюються.
- **`404`** — неіснуючий `:id`, а також `:id`, що не є додатним цілим (`/expenses/abc`), і невідомий маршрут. Fastify за замовчуванням повертає на помилку схеми `params` код `400`, тому помилка схеми `params` перетворюється на `404` у `setErrorHandler` (параметр шляху поки лише `:id`; якщо з'являться інші, правило треба переглянути), а невідомі маршрути обробляє `setNotFoundHandler`.
- **Тіло помилки** для `400`, `404` і `500` однакове: `{ "error": "<опис українською>" }`, `Content-Type: application/json`, інших полів немає. Його формують `setErrorHandler` і `setNotFoundHandler`.
- **`400`:** `error` — зрозумілий людині опис. Якщо порушено правило конкретного поля, опис називає це поле (наприклад `"amount: сума має бути більшою за 0"`); для помилок схеми Fastify і невалідного JSON достатньо загального `"Невалідні дані запиту"`. Тести перевіряють код і наявність непорожнього рядка `error`, а не точний текст.
- **`500`:** будь-яка неочікувана помилка. Тіло завжди `{ "error": "Внутрішня помилка сервера" }`, без стеку, SQL і внутрішніх повідомлень; подробиці лише в лозі сервера. Дані не змінюються: багатокрокові операції відкочуються транзакцією.
- **Інші `4xx` від Fastify** (наприклад `415` за непідтримуваного `Content-Type`, `413` за завеликого тіла) повертаються зі своїм кодом і тим самим форматом тіла.
- **`PUT`** — повна заміна полів ресурсу: відсутнє необов'язкове поле набуває значення за замовчуванням (`description` → `""`, `limit_amount` → без ліміту).

## Вхідні поля

| Поле | Тип і формат | Правило |
|---|---|---|
| `amount` | JSON-число | Округлення до 2 знаків, потім `Number.isFinite` і `> 0` (ADR 001). Рядок (`"12.5"`), `null`, відсутність — `400`. |
| `limit_amount` | JSON-число або `null` | Як `amount`; `null` або відсутність — без ліміту. Для «Інше» будь-який `PUT` — `400`. |
| `category_id` | ціле число | Має існувати; інакше `400`. |
| `description` | рядок | Відсутній — `""`; не рядок — `400`. |
| `spent_at` | `YYYY-MM-DD` | Реальна дата, не пізніша за `today` за `Europe/Kyiv` (ADR 003). `2026-02-30`, `2026-2-3`, `03.02.2026`, завтра — `400`. |
| `name` | рядок | `trim()`; порожній після `trim()` — `400`; дублікат серед **інших** категорій за `name_normalized` — `400` (ADR 002). |
| `is_default` | — | Встановлюється лише ініціалізацією БД; присутність у тілі `POST`/`PUT /categories` — `400`. |
| `month` (query) | `YYYY-MM` | Місяць `01`–`12`, не пізніший за поточний київський. `2026-13`, `2026-1`, майбутній, відсутній — `400`. |

## Відповіді

**Витрата:** `{ "id", "category_id", "amount", "description", "spent_at", "created_at" }`. `created_at` — UTC у форматі SQLite `YYYY-MM-DD HH:MM:SS`; UI переводить у київський час.

**Категорія:** `{ "id", "name", "limit_amount", "is_default" }`, де `is_default` — boolean.

**Створення та зміна** (`POST`/`PUT`) повертають об'єкт під ключем `expense` або `category` і, за перевищення, `warning`:

```json
{
  "expense": { "id": 12, "category_id": 3, "amount": 300, "description": "", "spent_at": "2026-11-05", "created_at": "2026-11-05 10:12:00" },
  "warning": { "category_id": 3, "limit_amount": 1000, "spent": 1250.5, "exceeded_by": 250.5 }
}
```

`warning` присутній, якщо **після зміни** округлена сума витрат категорії за 30 днів строго більша за ліміт, зокрема коли категорію було перевищено раніше або змінено лише її назву. Для витрати перевіряється цільова категорія (при перенесенні — нова). Інакше поля немає.

**Звіт за 30 днів** (`today = 2026-11-05`):

```json
{
  "from": "2026-10-07",
  "to": "2026-11-05",
  "total": 1500.3,
  "categories": [
    { "category_id": 3, "name": "Їжа", "total": 1000.2, "share": 66.67 },
    { "category_id": 1, "name": "Інше", "total": 500.1, "share": 33.33 }
  ],
  "limits": [
    { "category_id": 3, "name": "Їжа", "limit_amount": 1000, "spent": 1000.2, "remaining": 0, "exceeded_by": 0.2 }
  ]
}
```

- `share = Math.round(category_total / total * 10000) / 100`; сума часток відхиляється від 100% не більше ніж на `0.005 × N`.
- `categories` — лише категорії з сумою `> 0`, за спаданням суми; за періоду без витрат `total = 0`, `categories = []`, ділення не виконується.
- `limits` — усі категорії з лімітом, навіть зі `spent = 0`; `remaining = max(limit - spent, 0)`, `exceeded_by = max(spent - limit, 0)`, обидва округлені до 2 знаків.

**Місячний звіт:** `{ "month": "2026-10", "total", "categories": [...] }` — без `limits`, `limit_amount`, `spent`, `remaining`, `exceeded_by`.

**`GET /version`:** `Content-Type: text/plain`, тіло — короткий SHA (наприклад `a1b2c3d`). Визначається під час старту: зі змінної `GIT_SHA` (CI передає в неї вивід `git rev-parse --short HEAD`), інакше з `git rev-parse --short HEAD`; якщо обидва джерела недоступні — `unknown` з кодом `200`.
