# Контракт API — Expense Tracker

Доповнює [`spec.md`](../spec.md): spec описує намір і правила, цей файл — точні маршрути, заголовки, формати й коди. Запити й переклад помилок БД — [`db.md`](db.md). Схема БД — [`server/db/schema.sql`](../server/db/schema.sql).

## Маршрути

| Метод і шлях | Призначення | Успіх | Помилки |
|---|---|---|---|
| `GET /expenses` | Усі витрати, нові спочатку (`spent_at` DESC, `id` DESC) | `200` | `503` |
| `POST /expenses` | Створити витрату | `201` (+ `warning`) | `400`, `422`, `503` |
| `PUT /expenses/:id` | Замінити всі поля витрати | `200` (+ `warning`) | `400`, `404`, `503` |
| `DELETE /expenses/:id` | Видалити витрату, повернути видалену | `200` | `404`, `503` |
| `GET /categories` | Усі категорії за абеткою, «Інше» остання | `200` | `503` |
| `POST /categories` | Створити категорію | `201` | `400`, `422`, `503` |
| `PUT /categories/:id` | Замінити назву й ліміт | `200` (+ `warning`) | `400` (зокрема для «Інше»), `404`, `503` |
| `DELETE /categories/:id` | Перенести витрати в «Інше», видалити категорію, повернути її й кількість перенесених витрат | `200` | `400` (для «Інше»), `404`, `503` |
| `GET /reports/last-30-days` | Звіт за `[today - 29, today]` зі станом лімітів | `200` | `503` |
| `GET /reports/monthly?month=YYYY-MM` | Звіт за календарний місяць | `200` | `400`, `503` |
| `GET /version` | Короткий Git SHA | `200` | — |

Будь-який маршрут може також повернути `400` за невалідного `X-User` і `500` за неочікуваної помилки. `GET /version` до БД не звертається, тож `503` не повертає.

## Заголовки

### Запит

| Заголовок | Де | Формат | Поведінка |
|---|---|---|---|
| `X-User` | будь-який маршрут, необов'язковий | `^[A-Za-z0-9._-]{1,64}$` | Користувач-ініціатор (spec, розд. 3). Відсутній — `local`; невалідний — `400`. Це мітка, не автентифікація: сервер значення не перевіряє. |
| `X-Process-Id` | будь-який маршрут, необов'язковий | `^[A-Za-z0-9._:-]{1,64}$` | ID бізнес-процесу: одна дія користувача, кілька запитів (ADR 009). UI надсилає `crypto.randomUUID()` на дію. Відсутній або невалідний замінюється ID запиту; `400` не дає. |
| `X-Request-Id` | — | — | Ігнорується: ID запиту завжди генерує сервер, щоб він був унікальним (ADR 009). |
| `Idempotency-Key` | `POST /expenses`, `POST /categories`, необов'язковий | 1–128 символів `[A-Za-z0-9._:-]`, без лапок або в подвійних лапках (рядок RFC 8941) | Див. «Ідемпотентність». Невалідне значення — `400`. На інших маршрутах ігнорується. |

### Відповідь

| Заголовок | Коли | Значення |
|---|---|---|
| `X-Request-Id` | кожна відповідь, зокрема `4xx` і `5xx` | ID запиту (UUID), згенерований сервером; той самий, що `reqId` у логах |
| `X-Process-Id` | кожна відповідь, зокрема `4xx` і `5xx` | валідний вхідний `X-Process-Id` без змін, інакше той самий, що `X-Request-Id`; у логах — `bpId` |
| `Idempotent-Replayed` | повтор `POST` з відомим ключем | `true` |
| `Retry-After` | `503` | секунди, зараз `1` |

Невалідний `X-User` не заважає заголовкам-ID: відповідь `400` має і `X-Request-Id`, і `X-Process-Id`.

## Загальні правила

- **`400`** — невалідне тіло, query-параметр, `X-User` чи `Idempotency-Key`, а також порушення `UNIQUE` чи `FOREIGN KEY`, що оминуло перевірку в коді (`db.md`); дані не змінюються.
- **`404`** — неіснуючий `:id`, а також `:id`, що не є додатним цілим (`/expenses/abc`), і невідомий маршрут. Fastify за замовчуванням повертає на помилку схеми `params` код `400`, тому помилка схеми `params` перетворюється на `404` у `setErrorHandler` (параметр шляху поки лише `:id`; якщо з'являться інші, правило треба переглянути), а невідомі маршрути обробляє `setNotFoundHandler`.
- **`422`** — `Idempotency-Key` уже використано з іншим тілом запиту (ADR 010).
- **`409`** не використовується: перевірка ключа й запис ідуть в одній транзакції, тож стану «запит із цим ключем ще обробляється» інший запит не бачить (ADR 010).
- **`503`** — БД заблокована іншим процесом після всіх повторних спроб на сервері (ADR 010); дані не змінено. Тіло `{ "error": "База даних зайнята, спробуйте пізніше" }`, заголовок `Retry-After`. Клієнт може повторити запит після паузи; `POST` — з тим самим `Idempotency-Key`.
- **Тіло помилки** для `400`, `404`, `422`, `500` і `503` однакове: `{ "error": "<опис українською>" }`, `Content-Type: application/json`, інших полів немає. Його формують `setErrorHandler` і `setNotFoundHandler`.
- **`400`:** `error` — зрозумілий людині опис. Якщо порушено правило конкретного поля, опис називає це поле (наприклад `"amount: сума має бути більшою за 0"`); для помилок схеми Fastify і невалідного JSON достатньо загального `"Невалідні дані запиту"`. Тести перевіряють код і наявність непорожнього рядка `error`, а не точний текст.
- **`500`:** будь-яка неочікувана помилка. Тіло завжди `{ "error": "Внутрішня помилка сервера" }`, без стеку, SQL і внутрішніх повідомлень; подробиці лише в лозі сервера, у рядках з тим самим `reqId`, що й `X-Request-Id` відповіді. Дані не змінюються: багатокрокові операції відкочуються транзакцією.
- **Інші `4xx` від Fastify** (наприклад `415` за непідтримуваного `Content-Type`, `413` за завеликого тіла) повертаються зі своїм кодом і тим самим форматом тіла.
- **`PUT /expenses/:id`** спершу перевіряє `category_id`, потім існування витрати: неіснуючий `:id` разом з неіснуючою категорією дає `400`, а не `404`.
- **`PUT`** — повна заміна полів ресурсу: відсутнє необов'язкове поле набуває значення за замовчуванням (`description` → `""`, `limit_amount` → без ліміту).

## Ідемпотентність

Діє для `POST /expenses` і `POST /categories` з заголовком `Idempotency-Key` (ADR 010).

- Область ключа — пара (`X-User`, ключ): той самий ключ від іншого користувача — інший ключ.
- Відбиток запиту — SHA-256 від методу, шляху й тіла з відсортованими ключами; пробіли й порядок полів у JSON на нього не впливають. Значення за замовчуванням не підставляються: тіло з явним `"description": ""` і тіло без `description` мають різні відбитки.
- Ключ невідомий → запит виконується; успішний результат зберігається на 24 год.
- Ключ відомий, відбиток збігається → той самий код і те саме тіло, що й уперше (зокрема `warning` на момент першого запису), плюс `Idempotent-Replayed: true`. Нового запису немає.
- Ключ відомий, відбиток інший → `422`.
- Зберігаються лише успішні відповіді: запит, що отримав `400` або `503`, з тим самим ключем обробляється наново.
- Без заголовка кожен `POST` створює новий ресурс. `PUT` і `DELETE` ключа не приймають: `PUT` — повна заміна, повторний `DELETE` дає `404`.

## Вхідні поля

| Поле | Тип і формат | Правило |
|---|---|---|
| `amount` | JSON-число | Округлення до 2 знаків, потім `Number.isFinite`, `> 0` і `≤ 1 000 000 000` (ADR 001). Рядок (`"12.5"`), `null`, відсутність, `1000000000.01` — `400`. |
| `limit_amount` | JSON-число або `null` | Як `amount`, з тією самою верхньою межею; `null` або відсутність — без ліміту. Для «Інше» будь-який `PUT` — `400`. |
| `category_id` | ціле число | Має існувати; інакше `400`. |
| `description` | рядок | Відсутній — `""`; не рядок або довший за 500 символів — `400`. |
| `spent_at` | `YYYY-MM-DD` | Реальна дата, не пізніша за `today` за `Europe/Kyiv` (ADR 003). `2026-02-30`, `2026-2-3`, `03.02.2026`, завтра — `400`. |
| `name` | рядок | `trim()`; порожній або довший за 50 символів після `trim()` і NFC — `400`; дублікат серед **інших** категорій за `name_normalized` — `400` (ADR 002). Апострофи (`'`, `’`, `ʼ`) і гомогліфи (латинська `I` і кирилична `І`) не нормалізуються: `"Кав'ярня"` і `"Кавʼярня"` — різні назви. |
| `is_default` | — | Встановлюється лише ініціалізацією БД; присутність у тілі `POST`/`PUT /categories` — `400`. |
| `month` (query) | `YYYY-MM` | Місяць `01`–`12`, не пізніший за поточний київський. `2026-13`, `2026-1`, майбутній, відсутній — `400`. |

## Відповіді

**Витрата:** `{ "id", "category_id", "amount", "description", "spent_at", "created_at" }`. `created_at` — UTC у форматі SQLite `YYYY-MM-DD HH:MM:SS`; UI переводить у київський час.

**Категорія:** `{ "id", "name", "limit_amount", "is_default" }`, де `is_default` — boolean.

Довжини рахуються в кодових точках Unicode (`[...s].length`); для `name` — після `trim()` і NFC.

**`GET /categories`** повертає масив категорій, відсортований за `name` через `Intl.Collator('uk')`, а «Інше» завжди остання. Сортує чиста функція `core/`, яку викликає сервіс, а не `ORDER BY`: двійковий порядок SQLite ставить `Є`, `І`, `Ї`, `Ґ` не на свої місця (`"Їжа"` опинилася б перед `"Авто"`).

**Видалення** повертає видалений об'єкт. Повторний `DELETE` того самого `:id` дає `404`.

```json
{ "expense": { "id": 12, "category_id": 3, "amount": 300, "description": "", "spent_at": "2026-11-05", "created_at": "2026-11-05 10:12:00" } }
```

```json
{ "category": { "id": 3, "name": "Їжа", "limit_amount": 1000, "is_default": false }, "moved_expenses": 7 }
```

`moved_expenses` — кількість витрат, перенесених в «Інше»; `0`, якщо їх не було.

**Створення та зміна** (`POST`/`PUT`) повертають об'єкт під ключем `expense` або `category` і, за перевищення, `warning`:

```json
{
  "expense": { "id": 12, "category_id": 3, "amount": 300, "description": "", "spent_at": "2026-11-05", "created_at": "2026-11-05 10:12:00" },
  "warning": { "category_id": 3, "limit_amount": 1000, "spent": 1250.5, "exceeded_by": 250.5 }
}
```

`warning` присутній, якщо **після зміни** округлена сума витрат категорії за 30 днів строго більша за ліміт, зокрема коли категорію було перевищено раніше або змінено лише її назву. Для витрати перевіряється цільова категорія (при перенесенні — нова). Інакше поля немає.

**Звіт за 30 днів** (`today = 2026-11-05`):

```json
{
  "from": "2026-10-07",
  "to": "2026-11-05",
  "total": 1500.3,
  "categories": [
    { "category_id": 3, "name": "Їжа", "total": 1000.2, "share": 66.67 },
    { "category_id": 1, "name": "Інше", "total": 500.1, "share": 33.33 }
  ],
  "limits": [
    { "category_id": 3, "name": "Їжа", "limit_amount": 1000, "spent": 1000.2, "remaining": 0, "exceeded_by": 0.2 }
  ]
}
```

- `share = Math.round(category_total / total * 10000) / 100`; сума часток відхиляється від 100% не більше ніж на `0.005 × N`.
- `categories` — лише категорії з сумою `> 0`, за спаданням суми; за періоду без витрат `total = 0`, `categories = []`, ділення не виконується.
- `limits` — усі категорії з лімітом, навіть зі `spent = 0`; `remaining = max(limit - spent, 0)`, `exceeded_by = max(spent - limit, 0)`, обидва округлені до 2 знаків.

**Місячний звіт:** `{ "month": "2026-10", "total", "categories": [...] }` — без `limits`, `limit_amount`, `spent`, `remaining`, `exceeded_by`.

**`GET /version`:** `Content-Type: text/plain`, тіло — короткий SHA (наприклад `a1b2c3d`). Визначається під час старту: зі змінної `GIT_SHA` (CI передає в неї вивід `git rev-parse --short HEAD`), інакше з `git rev-parse --short HEAD`; якщо обидва джерела недоступні — `unknown` з кодом `200`.
