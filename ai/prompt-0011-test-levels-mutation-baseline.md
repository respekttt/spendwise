# Промпт 0011 — рівні тестів, одна команда, базовий мутаційний прогін «До»

---

## Роль і джерела істини

Ти працюєш у репозиторії Expense Tracker, гілка `task3`. Застосунок готовий (Завдання 2, PR #3 злито в `main`). Завдання 3 — тестування. Цей промпт — перша з двох частин:

- **0011 (цей):** розкладка тестів за рівнями, команди, Stryker, базовий мутаційний прогін «До». **Нових тестів і підсилень не пишеш.**
- **0012 (наступний):** нові unit-тести `reports.js`, підсилення за моєю класифікацією, прогін «Після», E2E-сценарій.

Між ними я сам класифікую вижилих мутантів, тому твій прогін «До» має показати стан **нинішніх** тестів.

Пиши код **лише** за документами, у такому порядку пріоритету:

1. `specs/testing.md` — увесь: рівні (розд. 2), правила мутацій (розд. 3), сценарії 1, 2, 4, 5, критерії 1, 3, 4, 6, 8.
2. `standards/adr/011-testing-levels-and-mutation.md` — увесь, зокрема «Розкладка й рівні», «Команди», «Мутації», «Перевірка (виконано 2026-11-21)».
3. `standards/adr/007-layers-routes-services-repositories.md` (тест імпортів), `004` (точні версії залежностей), `005` (CI).
4. `standards/checklist.md`, `standards/definition-of-done.md`.

Якщо документи суперечать один одному або чогось бракує — зупинись і спитай, не вигадуй. Спершу прочитай ці файли повністю, а також увесь `tests/`, `package.json`, `.gitignore`, `.github/workflows/ci.yml`, README. Документи в `spec.md`, `specs/`, `standards/`, `ai/` не редагуй; помилки в них опиши у звіті.

Кожне твердження цього промпту про стан коду («тест X імпортує Y», «у файлі є Z») перевір сам. Якщо код каже інше — зупинись і опиши розбіжність.

## Обсяг

### Робити

1. **Переїзд тестів у каталоги** (ADR 011, «Розкладка й рівні») — **першим, окремим комітом**, без змін у логіці тестів (лише шляхи імпортів):
   - `tests/unit/`: `core.test.js`, `time.test.js` — без тесту, що читає файли `server/core/` у пошуках `new Date()`;
   - `tests/integration/`: решта наявних файлів, тест на `new Date()` (окремим файлом), тести `defaultDbPath` зі `startup.test.js` (окремим файлом);
   - `tests/e2e/`: `startup.test.js` без тестів `defaultDbPath` і без жодного імпорту з `server/` (шлях до `server/main.js` рядком для запуску процесу — не імпорт);
   - `tests/helpers.js` → `tests/helpers/`;
   - після коміту `bun test` проходить з тією самою кількістю тестів, що й до переїзду (349). Якщо число змінилося — зупинись.
2. **Правила рівнів** у тесті, що сканує імпорти (зараз `tests/layers.test.js`, після переїзду — в `integration/`): `tests/unit/` імпортує лише `server/core/`, `bun:test` і `tests/helpers/`; `tests/e2e/` — нічого з `server/`. Самоперевірка, як для наявних правил: порушення ловиться, дозволене — ні. Окремий коміт.
3. **Команди** (ADR 011, «Команди»):
   - скрипти `package.json`: `test:unit`, `test:integration`, `test:e2e`, `test:all` (по черзі, зупинка на першому, що впав), `mutation` (`bunx stryker run`, без `--bun`); `ci` — `check`, `test:all`, `build`;
   - `Makefile` з двома цілями: `test` → `bun run test:all`, `mutation` → `bun run mutation`, і більше нічого;
   - `.github/workflows/ci.yml` не змінюй: він уже викликає `bun run ci`.
4. **Stryker** (ADR 011, «Мутації»):
   - `@stryker-mutator/core` у `devDependencies` з точною версією `10.1.1`;
   - `stryker.config.json` точно за ADR: `testRunner: "command"`, `commandRunner.command: "bun test ./tests/unit"`, `coverageAnalysis: "off"`, `mutate` — `server/core/**/*.js` без `server/core/errors.js`, `thresholds: { high: 90, low: 80, break: 80 }`, `reporters: ["clear-text", "progress", "html", "json"]`, звіти в `reports/mutation/`, `incremental: false`;
   - `.gitignore`: `.stryker-tmp/`, `reports/`;
   - README: команди рівнів, `make test` / `make mutation`, Node 22 — передумова лише для `mutation`.
5. **Базовий прогін «До»:** `bun run mutation` на тестах **після кроків 1–2** і **без жодних нових тестів**. Результат — `docs/mutation-report.md`:
   - шапка: дата, коміт, версії Bun, Node, Stryker, команда;
   - розділ «До»: підсумок (усього мутантів, убито, вижило, тайм-аут, без покриття, score) по всьому обсягу й по кожному файлу;
   - таблиця **кожного** вижилого мутанта: файл і рядок, мутатор, що змінилося (було → стало). Колонки «класифікація», «обґрунтування», «дія» лиши порожніми: їх заповню я;
   - порожні заготовки розділів «Таблиця гілок `reports.js`» і «Після».

   Якщо score нижче 80 %, команда завершиться з кодом `1`: це очікувано для «До», звіт однаково фіксуй.

### Не робити

- Нових тестів, підсилень наявних, `// Stryker disable` коментарів — це 0012, після моєї класифікації.
- Класифікації вижилих мутантів.
- E2E-сценарію зі `specs/testing.md`, сценарій 3 — це 0012.
- Змін у `server/`.
- Інших залежностей, крім `@stryker-mutator/core`.

## Пастки

1. **Stryker — лише через Node.** `bunx stryker run` працює, бо shebang запускає Stryker у Node; `bunx --bun stryker run` падає з `ChildProcessCrashedError` (ADR 011). Тести всередині Stryker однаково запускає `bun test`.
2. **Порядок обов'язковий.** «До» — на нинішніх тестах. Якщо щось дописати до прогону, розділ «До» перестане показувати прогалини «зелених» тестів (`specs/testing.md`, сценарій 4).
3. **Переїзд без змін логіки.** У коміті переїзду змінюються лише шляхи. Якщо тест без змін логіки не проходить на новому місці — зупинись.
4. **Шляхи до `server/main.js` і `schema.sql`** у тестах рахуються від файлу тесту (`import.meta.dir`); після переїзду на рівень глибше вони зміняться.
5. **`reports/` і `.stryker-tmp/`** не мають потрапити в коміт.
6. **Сервер для ручної перевірки** зупиняй `Ctrl+C` або за PID, не `taskkill /IM bun.exe`.

## Звіт

1. Повний вивід останнього `bun run ci` і підсумок `bun run mutation` (рядки clear-text з таблицею по файлах) з кодами виходу.
2. Коміти (хеш і повідомлення).
3. Розкладка: який файл куди переїхав; кількість тестів до і після переїзду по рівнях.
4. `specs/testing.md` і ADR 011 — пункт за пунктом для цього етапу: виконано / ні.
5. Відхилення від документів і де вони мовчать.
6. Що здалося тобі в списку вижилих мутантів очевидною прогалиною — **окремим списком, без класифікації в звіті**: рішення за мною.
